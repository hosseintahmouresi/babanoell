نسخه 8.4.6.25
================

GreenPay / BKI (افزایشی و مستقل از گردش اصلی سامانه)
---------------------------------------------------
- اضافه شدن Integration مستقل GreenPay بدون وابسته کردن وضعیت‌ها و مراحل اصلی بابانوئل به سرویس خارجی.
- هنگام ورود واقعی پرونده به وضعیت «تأیید مدارک»، در صورت فعال بودن تنظیم، عملیات کسری GreenPay به صورت Async در صف قرار می‌گیرد.
- مبلغ کسری دقیقاً از facility_amount (فیلد «مبلغ تسهیلات» محاسبه‌شده) و با fallback به loan_amount برای پرونده‌های قدیمی، با واحد ریال Snapshot می‌شود؛ هیچ تبدیل ×10 انجام نمی‌شود.
- RefNumber ثابت و یکتا به شکل MLR-GP-{request_id} برای جلوگیری از تولید چند مرجع برای یک پرونده.
- جدول مستقل mlr_greenpay_transactions با UNIQUE روی request_id برای جلوگیری از دوبارکسر.
- وضعیت‌های queued / processing / awaiting_otp / success / failed / unknown.
- در پاسخ‌های Timeout، خطای شبکه، HTTP 5xx یا پاسخ 2xx نامشخص، تراکنش unknown می‌شود و هرگونه Retry خودکار متوقف می‌شود.
- تراکنش success هرگز دوباره صف‌بندی نمی‌شود.
- پردازش stale که نتیجه قطعی ندارد به unknown تبدیل می‌شود تا دوبارکسر رخ ندهد.
- ثبت Eventهای GreenPay در تاریخچه پرونده و Notification برای خطاها/وضعیت‌های نیازمند رسیدگی.
- هیچ خطای GreenPay باعث Rollback یا تغییر خودکار وضعیت پرونده نمی‌شود.

محیط تست GreenPay
-----------------
- FromPocketNumber پیش‌فرض Sandbox: 1262010000002551
- ToPocketNumber پیش‌فرض: خالی
- OTP پیش‌فرض Sandbox: 123456
- Password در Sandbox، در صورت خالی بودن تنظیمات: 1
- امکان Bypass کامل sendPurchaseOTP در Sandbox مطابق سناریوی تست.
- SendTime در حالت Bypass از زمان تهران ایجاد می‌شود.

محیط عملیاتی GreenPay
---------------------
- درخواست OTP از sendPurchaseOTP انجام و تراکنش در وضعیت awaiting_otp نگهداری می‌شود.
- OTP در دیتابیس ذخیره نمی‌شود و مدیر می‌تواند آن را فقط برای همان درخواست در صفحه تراکنش‌ها وارد و کسری را نهایی کند.
- HTTPS در محیط Production اجباری است و SSL verification غیرفعال نمی‌شود.
- API Client از WordPress HTTP API استفاده می‌کند و به WooCommerce وابسته نیست.

پنل مدیریت GreenPay
-------------------
- اضافه شدن زیرمنوی «تراکنش‌های GreenPay».
- نمایش مبلغ Snapshot، وضعیت پرونده، وضعیت تراکنش، RefNumber، کیف مبدأ Mask شده، HTTP Code و خطا.
- امکان پردازش دستی queued، Retry فقط برای failed قطعی، و ورود OTP برای awaiting_otp.
- unknown عمداً Retry ندارد و نیازمند استعلام GreenPay است.
- امکان صف‌بندی اختیاری پرونده‌های موجود در «تأیید مدارک» بدون تراکنش قبلی.
- امکان تست اتصال و دریافت Token.

تنظیمات و حفظ اطلاعات API
--------------------------
- اضافه شدن تنظیمات کامل GreenPay به همان صفحه «تنظیمات API».
- GreenPay پس از آپدیت به صورت Safe-by-default غیرفعال می‌ماند تا مدیر پس از کنترل Credentialها آن را فعال کند.
- Password و API Key هنگام ذخیره با فیلد خالی پاک نمی‌شوند.
- مشکل پاک شدن Client Secret شاهکار هنگام ذخیره فرم با input خالی برطرف شد.
- Client ID، Client Secret و Owner NID شاهکار هنگام ارسال مقدار خالی مقدار قبلی را حفظ می‌کنند.
- Snapshot پشتیبان non-autoloaded از Credentialهای API ساخته می‌شود و در صورت خالی شدن تصادفی بعد از Update/Deployment، تنظیمات قابل بازیابی خودکار هستند.
- در صورت وجود تنظیمات افزونه قدیمی WooCommerce BKI، Credentialهای خالی GreenPay یک‌بار از woocommerce_bki_wallet_settings مهاجرت داده می‌شوند.

نکات سازگاری
-------------
- هیچ جدول یا فیلد اصلی loan_requests برای GreenPay تغییر داده نشده است.
- منطق اعطا، تسویه، محاسبه‌گر، پیامک، نقش‌ها و داشبوردهای موجود وابسته به نتیجه GreenPay نشده‌اند.
- Trigger GreenPay از یک Action عمومی پس از موفقیت تغییر وضعیت استفاده می‌کند تا Core Workflow مستقل باقی بماند.

کنترل کیفیت تکمیلی
------------------
- Trigger ورود به «تأیید مدارک» در مسیر بارگذاری مدارک نهایی متقاضی/پذیرنده نیز پوشش داده شد؛ بنابراین Integration به یک صفحه مدیریت خاص وابسته نیست.
- خطای ثبت صف GreenPay در دیتابیس اکنون Event/Notification/Log تولید می‌کند و بدون ارسال درخواست مالی متوقف می‌شود.
- در صورت DISABLE_WP_CRON هشدار مدیریتی نمایش داده می‌شود تا Cron واقعی سرور فراموش نشود.
- دو Filter توسعه‌ای `mlr_greenpay_from_pocket_number` و `mlr_greenpay_to_pocket_number` برای اتصال آینده‌ی Pocket اختصاصی هر پرونده اضافه شد، بدون تغییر ساختار اصلی پرونده‌ها.
